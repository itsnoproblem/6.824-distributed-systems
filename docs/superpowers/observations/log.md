### Observation 5: Professional docs must avoid AI-tell vocabulary and constructions

**Status:** ACTIONED (2026-08-12 — feedback memory `professional-writing-no-ai-tells.md` written to auto-memory in the same session)
**Date:** 2026-08-12
**Session context:** Drafting an exec-facing pilot proposal memo for AI code review tools
**Target:** auto-memory (feedback memory `professional-writing-no-ai-tells.md` written this session)

**Issue:** The user preemptively instructed that documents intended for professional audiences must avoid "Claudisms": em dashes, "load bearing", and "it's not A nor B, but full on C" constructions. This was given as a standing constraint, not a one-off edit.
**Suggested improvement:** When producing prose deliverables for human audiences (memos, proposals, docs), write in plain professional style: no em dashes, no AI-associated stock vocabulary, no "not X but Y" rhetorical constructions.
**Principle:** Deliverables read by the user's colleagues carry the user's voice; recognizable LLM stylistic tics undermine credibility of the document and its author.
